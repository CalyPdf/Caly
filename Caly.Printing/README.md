# Caly.Printing

[![Printing](https://github.com/CalyPdf/CalyPdf/actions/workflows/tests-printing.yml/badge.svg)](https://github.com/CalyPdf/CalyPdf/actions/workflows/tests-printing.yml)

Printing support for Caly's desktop builds. Each page is rendered to a bitmap with the same Skia pipeline the viewer uses, then handed to the platform's print spooler.

| Project | Purpose |
|---|---|
| `Caly.Printing.Core` | Code shared by both platforms: page-to-bitmap rendering, JPEG encoding, greyscale conversion (`PrintServiceHelper`) and layout maths for auto-orientation, pages-per-sheet cells and fit modes (`PrintLayout`) |
| `Caly.Printing.Windows` | `WindowsPrintService`: the Win32 print spooler through GDI, with P/Invoke generated by CsWin32 |
| `Caly.Printing.Unix` | `UnixPrintService`: CUPS over IPP on Linux and macOS, using SharpIppNext |
| `Caly.Printing.Tests` | Tests for the three projects above |

The `IPrintService` interface and its settings types live in `Caly.Core` (`Services/Interfaces/IPrintService.cs`). `Caly.Desktop/DesktopApp.cs` registers `WindowsPrintService` on Windows and `UnixPrintService` everywhere else.

## How a document is printed

### Windows

- **Discovery:** `EnumPrinters` (level 4, local printers and connections).
- **Capabilities:** `DeviceCapabilities` for landscape and colour support.
- **Printing:** a printer device context (`CreateDC`), then `StartDoc`, and for each sheet `StartPage`, `StretchDIBits`, `EndPage`.
- **Settings:** orientation and monochrome are written into the driver's `DEVMODE`. With automatic orientation the `DEVMODE` is updated per sheet (`ResetDC`).
- **Pages per sheet:** GDI has no N-up setting, so Caly tiles the pages onto the sheet itself.
- **Greyscale:** if the driver does not keep the monochrome setting, Caly converts the bitmap to greyscale before drawing it.

### Linux and macOS

- **Discovery:** `CUPS-Get-Printers` on `ipp://localhost:631/`, falling back to `lpstat -a`.
- **Capabilities:** `Get-Printer-Attributes`. If the request fails, conservative defaults are used.
- **Printing:** one `Create-Job`, then one `Send-Document` per page. Each page is a JPEG rendered at 200 DPI.
- **Settings:** orientation, colour mode, pages per sheet and scaling are sent as IPP job attributes (`orientation-requested`, `print-color-mode`, `number-up`, `print-scaling`) and applied by CUPS. With automatic orientation Caly rotates landscape pages itself.
- **Greyscale:** if the printer advertises no monochrome mode, Caly converts the bitmap to greyscale before sending it.
- **Cleanup:** if printing fails or is cancelled part-way, the job is closed with a final empty document so it does not stay open in the queue.

## Tests

```bash
dotnet test Caly.Printing/Caly.Printing.Tests
```

The project holds two kinds of test.

**Unit tests** run anywhere: IPP attribute mapping, the job template, layout maths, the bitmap helpers, and the test plumbing itself.

**Spooler tests** print to a real print spooler and check what the spooler received. They run in the [`Printing` workflow](../.github/workflows/tests-printing.yml) on Windows x64, Windows arm64, Linux x64, Linux arm64 and macOS arm64. Everywhere else they are skipped.

### What controls the spooler tests

| Variable | Meaning |
|---|---|
| `CALY_TEST_PRINTER` | Name of the test queue. The spooler tests print to this queue and no other |
| `CALY_TEST_PRINTER_OUTPUT` | Windows only: the PDF file the test queue writes each job to |

- If `CALY_TEST_PRINTER` is not set, the spooler tests are skipped, so running the tests on your machine never sends anything to a real printer.
- On GitHub Actions (`GITHUB_ACTIONS=true`) a missing `CALY_TEST_PRINTER` fails the tests instead, so a broken provisioning step cannot pass unnoticed.
- The Windows tests are skipped on Linux and macOS, and the CUPS tests are skipped on Windows.

The document that gets printed is a small A4 PDF built in memory (`PrintTestDocument`), with one page per requested orientation.

### Windows spooler tests

The workflow creates a printer that uses the inbox **Microsoft Print To PDF** driver on a local port named after a file path. The spooler then writes every job to that file, with no Save dialog:

```powershell
$out = Join-Path $env:RUNNER_TEMP 'caly-print\out.pdf'
Add-PrinterPort -Name $out
Add-Printer -Name CalyTestPrinter -DriverName 'Microsoft Print To PDF' -PortName $out
```

Each test prints, waits for the spooler to finish writing the file, and opens it with PdfPig. The tests cover:

- the queue is listed and reports its capabilities;
- one sheet per page, in portrait or landscape as requested;
- automatic orientation follows each page;
- two pages per sheet halves the sheet count;
- progress is reported up to the page count;
- an unknown printer name fails with an exception.

### CUPS tests (Linux and macOS)

The workflow creates a queue with CUPS' own Generic PostScript driver whose output is discarded:

```bash
sudo lpadmin -p CalyTestPrinter -E -v file:///dev/null \
  -m drv:///sample.drv/generic.ppd -o printer-error-policy=abort-job
```

On Linux the workflow first installs `cups` and `cups-filters`; macOS ships with CUPS.

CUPS really converts every JPEG that Caly sends, so a job only completes if CUPS could process it. The output itself is thrown away, so the tests read CUPS' record of the job back over IPP (`CupsQueue`). The tests cover:

- the queue is listed with an IPP address;
- a two-page document becomes one completed job with two documents, named after the file;
- landscape, monochrome, two pages per sheet and actual-size scaling arrive on the job as IPP attributes;
- progress is reported up to the page count;
- an unknown queue fails with an exception;
- a job cancelled after its first page is closed, not left open in the queue.

### Known limits

- The CUPS tests do not look at the printed output, only at CUPS' job record. Page content and layout are checked on Windows only.
- The CUPS discovery test passes whether the queue was found through `CUPS-Get-Printers` or through the `lpstat` fallback.
- `UnixPrintService.GetPrinterCapabilitiesAsync` has no spooler test: on failure it returns defaults that a healthy queue is also likely to report, so a test could not tell the two apart.

### Running the spooler tests on your own machine

This is optional; the tests are written for CI. Create the queue with the commands above (on Windows, replace `$env:RUNNER_TEMP` with a folder of your choice), set the variables, and run the tests:

```powershell
# Windows
$env:CALY_TEST_PRINTER = 'CalyTestPrinter'
$env:CALY_TEST_PRINTER_OUTPUT = $out
dotnet test Caly.Printing/Caly.Printing.Tests
```

```bash
# Linux / macOS
CALY_TEST_PRINTER=CalyTestPrinter dotnet test Caly.Printing/Caly.Printing.Tests
```

This adds a printer to your system. Remove it afterwards with `Remove-Printer -Name CalyTestPrinter` and `Remove-PrinterPort -Name $out` on Windows, or `sudo lpadmin -x CalyTestPrinter` on Linux and macOS.
